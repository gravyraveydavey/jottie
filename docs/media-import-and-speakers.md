# Media import and speaker testing

The manager's top Import button and File → Import accept multiple audio/video files together with transcript documents. After selection the manager opens Queue. Folder selection recursively imports text/Word transcripts only; media must be selected explicitly. The library-only command reports that audio processing requires the full app.

## Speaker-labelled documents

Word, text and Markdown imports now recognise explicit Teams-style `Full Name   m:ss` / `Full Name   h:mm:ss` speaker headings, including Word's Unicode line/paragraph separators. Each nonempty turn preserves the supplied name, speech and start timestamp. Equal timestamps and overlapping turns remain separate; no exact speech-end times are invented. A supplied overall duration can bound the final turn. A recognised English Teams date header supplies the meeting date, interpreted in the Mac's local timezone because these exports provide no timezone offset.

Title/date headers and transcription start/stop notices are not attributed to a speaker. The full extracted original remains in SourceTextHistory, and the preamble is retained in document metadata. Unrecognised layouts stay intact as one unknown passage; the parser does not infer people from ordinary prose. Document labels are identified as transcript sources, not as acoustic voice detection. Names can be matched against the local BambooHR cache without claiming they came from an invitation.

Imports track the parser revision separately from the file digest, so importing unchanged bytes after an importer upgrade can update the same meeting rather than create a duplicate. On normal library reconciliation, older collapsed imports can also be repaired from their retained text without re-opening the original Word file or invoking Codex. Automatic repair requires an unchanged single unknown passage and no manual speaker corrections. Meeting identity, manual filing, stars and previous transcript/analysis history remain intact. A changed transcript invalidates the current analysis; normal opted-in processing can generate a new revision using the existing settings. Explicit re-import preserves manual passage corrections only when the passage itself is unchanged.

## Audio and video

Media goes through the existing native AVFoundation importer: inspect an audio track, hash the source for deduplication, extract/downmix the first audio track to a private staged mono M4A, write session metadata, then hand a complete session to the ordinary transcription queue. A movie's video track is not retained. No ffmpeg or Python runtime is required. Files must use a codec/container macOS can decode; unsupported or silent videos are reported individually and do not stop the batch. The original file is never moved, edited or deleted.

Queue shows conversion status, import failures/duplicates, and unfinished transcription sessions, separately from analysis/knowledge/publication jobs. Failed/deferred sessions retain audio and can be retried. The filesystem remains the durable transcription queue; completed normalized sessions resume after restart. An interrupted conversion is unpublished staging and must be selected again. Conversion result messages are session-local, not a durable import history.

Both Parakeet and Whisper use the same optional Community-1 speaker-separation adapter. Switching recognizers alone does not add diarization. Parakeet supplies word timings; the current Whisper adapter supplies segment timings. A coarse segment spanning several voices remains unresolved unless one voice clearly dominates: the app does not guess where to cut its text. WhisperX adds a distinct word-alignment and diarization pipeline and is not the Whisper option in Jottie.

With separation enabled, microphone and system tracks are both processed. Remote voices retain separate `them N` labels. One confidently detected microphone voice retains `me` and the configured owner name. Multiple microphone voices get `me N`; uncertain microphone passages get `me unknown`, so neither automatically inherits the owner's identity. Imported recordings use anonymous `speaker N` labels. Track-local IDs are not cross-track voice identities: echo filtering still removes duplicate playback speech, but the app does not claim a shared person across tracks without evidence/correction.

The anonymous labels feed the existing calendar/BambooHR/text-evidence reconciliation. A stable microphone cluster can propagate an anchored identity under the same confidence/evidence rules as a remote cluster; unresolved passages cannot. Similar voices, crosstalk and short turns can still cause merges or splits. Voice-separation accuracy must be judged on recordings with known participants and speaker turns, separately from synthetic pipeline tests.

Transcription logs report model cluster counts and assigned/unresolved segment counts per track, without adding transcript text or voice embeddings. Existing text-only meetings cannot gain acoustic diarization: re-import the original audio/video if it is available. Successful durable transcription deletes only Jottie's normalized temporary audio; summary success is not required for cleanup.

The supplied whisper-web reference uses Transformers.js in a worker. Its useful separation of media decoding and recognition already has native equivalents in Jottie. No source code or dependency from that project is required for this integration.

## Reviewed transcript cleanup — 29 October 2026

The Transcript tab offers **Clean up transcript**, a manual text-only Codex action using the saved executable, model and reasoning effort with ChatGPT authentication. It does not enable automatic summaries, use an API fallback or upload audio. The inline disclosure describes the transcript, invitation, matched local directory data and recording context sent by the action. No device classification automatically triggers a Codex call.

New recordings retain typed input/output device facts at capture start and route changes. Playback prefers the call app's unique reported output; unavailable or ambiguous routing explicitly falls back to the system default. Connection type (USB, Bluetooth, built-in, display, AirPlay or virtual/aggregate) is separate from physical terminal type. Only explicit Core Audio terminal evidence classifies speakers/headphones; unknown devices stay unknown. Existing captures can recover device names and echo-processing metadata without guessing their physical type. **Recording context…** lets the user confirm speakers/headphones/unknown and add a note while preserving detected facts and their timestamps. Speaker playback or previously detected cross-track matches suggest review; local echo filtering remains enabled independently of hardware.

Cleanup returns passage-scoped proposals rather than a rewritten transcript blob. Long meetings are covered in bounded chunks with neighboring context; only the owning chunk can edit a passage. Oversized individual passages fail explicitly rather than being truncated. The fixed prompt preserves wording, chronology, numbers, negation, commitments and uncertainty. Invitation/role context does not prove attendance or identity. Exact source wording, known IDs and speaker evidence are checked locally. Whole-passage duplicate removal must cite nearby speech under another source label. Uncertain changes start unchecked, speaker suggestions always start unchecked, and manual assignments and document names cannot be overwritten by suggestions.

**Review cleanup** opens the nested **Cleanup suggestions** tab beneath Summary / Transcript / Speakers. **Original transcript** shows the saved version. The suggestions tab uses the full detail width for a coherent transcript preview; expandable change details retain original/proposed wording, reasons, uncertain suggestions and independently selectable speaker proposals. **Overwrite transcript** applies selected changes in place without a review popup. Applying selected changes checks the source and context revision again and cannot delete both copies of a cited duplicate. Joined turns retain the first source ID, acoustic label and start timestamp, and extend to the final fragment. Constituent IDs remain in a source map and original history. Original wording remains in canonical history and in the meeting's original-transcript snapshot. Applied cleanup history records model, effort, prompt revision, selected changes and reasons. Unchanged source rescans preserve reviewed text and user-confirmed recording context. An actual source replacement invalidates the cleanup selection. **Show original transcript**, **Restore original transcript**, and **Cleanup history…** are available from the transcript menu. Restoring wording preserves explicit speaker corrections and applied cleanup history.

Applying or restoring text archives the previous summary and requires explicit summary regeneration; background processing does not upload the changed transcript automatically. A new summary is validated against the selected transcript revision, and its segment IDs still link to retained original passages. Markdown includes cleanup/current/original revision provenance. MCP `get_transcript` defaults to the current reviewed text and accepts `view=original` with independent pagination and the original revision. Search and ordinary exports use selected text. Review proposals and original audio/transcript capture receipts are not published as remote content.

An operational cleanup lease prevents concurrent calls from separate app instances and protects an active call from the development installer. Cancellation/failure leaves the transcript unchanged, retains any previous draft and never queues an automatic cleanup retry. Synthetic fixtures and mocked structured responses test the workflow without submitting real meetings.

### Sentence consolidation and inline review — 29 October 2026

Cleanup now joins consecutive nearby fragments belonging to the same confirmed person, even when their acoustic labels differ. A different confirmed speaker, unresolved shared channel, long pause or bounded turn limit prevents a join. Local preparation removes English hesitation forms such as um/uh/erm, while retaining punctuation, negation, ordinary words and meaningful uh-huh responses. These are review proposals, not silent edits. The prompt then resolves duplicated boundary words, repeated false starts, misheard wording and echo within/across turns, preserving unique clauses and interrupted speech without inventing an ending.

**Cleanup options** independently controls joining and filler removal, accepts a confirmed speaker count and provides **Additional cleanup instructions**. These preferences are separate from device notes and included explicitly in the prompt. The model receives each prepared passage's resolved speaker and confirmation status rather than a repeated meeting-wide manual-assignment dictionary. Confirmed counts constrain identities without treating invitees as detected people. Existing speaker corrections take precedence.

Compact requests omit repeated metadata, and model responses no longer echo entire original passages; original text and constituent IDs are attached locally. A read-only estimate on the reported recording reduced 1,046 fragments to approximately 279 turns and seven AI sections to two. This is a payload/call-count estimate, not a measured runtime guarantee. Per-section progress and cancellation are visible. Old-prompt previews require regeneration. Completed suggestions open with options collapsed so the full-width transcript is immediately visible. Individual edits and speaker suggestions remain reviewable before **Overwrite transcript**.

Every merged passage maps to its constituent original IDs in `transcriptSourceSegmentIDs`; MCP returns this bounded map alongside current passages. Restore clears the derived map and returns the original passages, retaining manual names and cleanup history. A later manual speaker correction to a joined passage also updates its retained constituent IDs, so restoring cannot silently lose that correction. Cleanup preferences remain local and are excluded from publication metadata.

## Reimport after permanent deletion

Media deduplication now checks each matching capture receipt against the canonical library and Trash. An active or pending recording remains a duplicate. A recoverable meeting in Trash stays recoverable and the import result explicitly directs the user to restore it, or empty Trash before importing afresh. Once permanently deleted, that old receipt no longer blocks an explicit import of the same source bytes. The importer creates a fresh session and meeting, then runs normal transcription and optional analysis. It still finds a current duplicate when older deleted receipts have the same hash, including after restart.

The old source tombstone is retained to prevent background scanning from resurrecting the deleted session. This does not restore the deleted meeting, clear the work ledger/publication receipts or modify the original media. If the library's status cannot be read, the item reports a failure rather than silently creating a duplicate. The production importer uses the same status adapter at startup and when adopting a changed recordings directory.

The regression first reproduced the reported failure, then verified an isolated synthetic import → Trash → restore → permanent deletion → fresh import → duplicate check → restart sequence. It asserts a fresh meeting ID, suppression of the old capture, continued deduplication of the new one and unchanged original source bytes. Additional checks cover Trash-specific result copy and safe handling of unreadable library state. The lifecycle uses a mocked normalizer and prepared transcript; existing native audio/video normalization tests cover the decoder separately. No user recordings were deleted or re-imported for validation.
