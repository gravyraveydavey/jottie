# Calendar context and local speaker separation

The reported failure had two independent causes. Recent captures had no calendar invitees. The saved selection pointed at `Default — Calendar`, while the Exchange calendars were unchecked; the app therefore had no invitation identities to reconcile with the successfully synced BambooHR cache. Separately, Parakeet's per-track transcription assigned the entire system track to `them`. That label represented an audio channel, not a detected individual voice.

Synthetic regression tests reproduced a third issue: importing an unchanged transcript again ignored changed calendar metadata. Another test reproduced email matching failures when addresses included whitespace or an upper-case `MAILTO:` prefix. These are now covered at their repository/directory boundaries.

## Calendar and directory behaviour

Integrations lists accounts alongside calendar names and reports the selected available calendars. The actual work calendar must be selected and saved; Jottie does not guess between Exchange calendars or combine unrelated overlapping events. Calendar access granted from Integrations is picked up by the capture watcher without requiring a restart. A refreshed EventKit store avoids stale calendar objects after account changes. Recording directly after initial access still depends on macOS making the grant available.

The Speakers tab now exposes the attached event, the invitation roster, **Find / change calendar event**, and **Refresh directory matches**. The event chooser reads a bounded set of events near the recording from the saved calendar selection. Choosing an event stores a canonical snapshot and manual override, then refreshes local BambooHR matches without contacting Codex. Existing summaries remain versioned and change only on explicit regeneration. Source rescans do not override a manually attached event or manual speaker corrections.

Calendar identities include available work emails and the organiser, with duplicate invitees removed. Directory matching remains email-first and unique-name-only when no email exists; whitespace and mailto casing are normalised. Ambiguous names remain unresolved. A directory match does not establish attendance or identify a speaker channel. Reconciled assignments carry the uniquely matched job title; corrections can also select a directory person to fill it.

## Distinguishing remote voices

Under Settings → Recording → Local speech models, **Local speaker separation** downloads the FluidAudio offline Community-1 model set into Jottie's own model directory. A successful download validates the models and enables `transcription.separate_speakers`. It is off for existing installations until this explicit setup. Models are loaded directly through Core ML during transcription; missing or corrupt assets cannot trigger a download fallback. Deleting the models disables separation.

When enabled, the remote track (or a mono imported recording) is diarized locally. Parakeet retains its real word timestamps so a sentence containing two voices can become separate anonymous speaker turns without guessing where to divide its text. Microphone and remote track offsets remain intact. Ambiguous overlap, silence and coarse segments without sufficient timing evidence stay unresolved. Other local engines without word timings can only assign an existing segment when one voice clearly dominates it. Voice embeddings remain transient inside the model and are not stored as reusable voice profiles or sent to BambooHR/Codex.

The transcription remains incomplete if the requested separation step fails. Audio is preserved for retry; after the complete transcript is committed, normal text-only cleanup applies. No audio is sent to a cloud service. Only anonymised labels/times and the transcript reach the library and opted-in text analysis.

This is probabilistic voice separation, not verified identity recognition. Similar voices, crosstalk, quiet speakers and poor audio can still produce unresolved or incorrect voice clusters. Invitees and transcript evidence help propose names afterwards; no one-to-one mapping is inferred from invitation order. The UI says **speaker labels** rather than claiming the number of people from the channel count.

## Existing records and validation limits

Attendee context and directory matches can be repaired for existing records without audio. A transcript whose audio has already been deleted cannot be reliably re-diarized; Jottie does not invent missing voice boundaries from a roster. Shared-channel warnings explain that renaming `them` affects all of its passages. New separation applies to future transcription, or recovery/retranscription only where audio still exists.

Tests use invented audio/timing and directory fixtures. They cover metadata-only updates, manual event precedence, email normalisation, preservation of corrections, two voices in one ASR span, overlap, coarse timings, track offsets and audio retention on missing models. Live meeting accuracy remains a separate validation step.

Model source: [FluidInference speaker-diarization-coreml](https://huggingface.co/FluidInference/speaker-diarization-coreml). Community-1 conversion artifacts use CC BY 4.0; source attribution and provenance are linked in THIRD-PARTY-NOTICES.md. Model files are downloaded separately and are not bundled into Jottie's application.

Validation outcome: all 772 inherited/capture tests and 46 Jottie tests passed, as did 30 packaging-script checks (two optional skips). A separate opt-in check downloaded the public Community-1 artifacts and loaded all Core ML models successfully without any real recording. That check exposed and fixed a mismatch between the SDK repository slug and its local cache-directory alias; runtime now uses the SDK-provided folder name. Packaging passed signature, embedded-framework launch and macOS 14.2 checks. Unrelated icon work was left unchanged.

The user's chosen **Exchange — Calendar** was selected and saved, with the former Default calendar deselected. ## Reconciled identities and aliases — 28 October 2026

Jottie separates acoustic diarization from identity reconciliation. The recognizer's segment IDs, timestamps, original text and acoustic speaker labels remain unchanged. `meeting.json` now carries optional `speakerAttributions` keyed by segment ID, including canonical name, job title, employee ID where matched, method, confidence score, reasoning basis, exact evidence and analysis revision. The official readable transcript, Markdown exports, search projection and native transcript render these names. MCP returns paginated original segments alongside bounded display-name and attribution maps and a speaker revision. Previous assignment snapshots are retained in `SpeakerHistory`; analysis evidence remains in its versioned analysis record.

Codex analysis receives invitation identities, directory names/titles/aliases, existing manual corrections and ordered transcript segments. It considers self-identification, named question/response adjacency, exclusion of the person being addressed, aliases, consistent separated voices and topic/role context. Merely discussing someone is not evidence of their attendance. Role context and elimination alone cannot apply an identity. Suggestions below the automatic threshold remain available in the correction UI.

Automatic application requires confidence at least 0.85, validated exact evidence and an introduction or direct named question/response anchor. The confidence is an AI assessment, not a measured probability of correctness. Local checks require an actual introduction phrase, or a named question followed by a cited response from a different acoustic label. Shared aliases must be unique within the matched roster to serve as an anchor. Consistent turns of an acoustically separated label may inherit an anchored identity when Codex explicitly requests voice consistency and there are no competing identities for that label. Shared `them` channels receive only individually supported passage assignments; they cannot inherit an identity over the whole channel. Contradictory assignments for one passage remain unknown. These checks deliberately leave some plausible conversational inferences unresolved. Introduction and direct-address phrase checks currently cover English; unsupported language forms remain suggestions for correction rather than automatic assignments.

Alias hints are derived locally from full names, given names, surnames and a small nickname/spelling dictionary (for example David/Dave, Fiona/Fi, Jonathan/Jonathon/Jon, Welch/Welsh and Barrett/Barret). They are possible spellings, never globally unique identity keys. Two people called Jon remain separate. Settings → Integrations → Name aliases lets the user add company-specific variants. Custom aliases are stored in the durable `directory_aliases` table in `directory.sqlite`, survive a refresh for the same employee/company, and are removed when the employee disappears or the company changes/disconnects. They are independent of the disposable search index. An invitation with an email still matches by email only; an alias cannot override a conflicting email. Updating aliases affects the next explicit analysis/regeneration rather than rewriting completed summaries.

The Speakers tab displays reconciled voices, directory roles, invite/name-mention/BambooHR/user/AI sources and expandable evidence. Unknown voices are numbered `Speaker X`. Corrections can target all passages in a row or selected passages with transcript excerpts. Blank corrections explicitly mark passages unknown and block subsequent AI reassignment. Manual passage assignments outrank saved label names and AI; saved label corrections also outrank AI. Invited but not detected is a separate section, with a mention indicator where applicable. This section is not an absence report: silent attendees and people only discussed cannot be distinguished from text alone.

General settings exposes the existing capture `user_name` preference with directory autocomplete; Recording retains the same field. Apply saves to the same Jottie preference used by capture. New capture imports use this name for the microphone track even when summaries are disabled. Changing the default does not overwrite existing meeting corrections. Explicit regeneration can fill a previously unnamed microphone track from the current configured name.

### Transcription engine choice

Retain Parakeet plus the separate local Community-1 diarizer for the pilot. Parakeet supplies words and times; the diarizer supplies voice clusters; Codex reconciles text evidence with people. This is the separation recommended by [FluidAudio's offline diarization documentation](https://github.com/FluidInference/FluidAudio#speaker-diarization). Similar voices, speakerphone echo, very brief turns, crosstalk and timing errors can still merge or fragment clusters. Recording quality and independently captured participant tracks, where available, provide stronger evidence than text heuristics.

[Whisper](https://github.com/openai/whisper) is a speech recognition model, not a replacement for this identity layer. It remains an available local engine, but Jottie's current Whisper adapter emits segment times with token timestamps disabled. Switching to it alone therefore does not solve mixed-stream speaker attribution, and currently provides less precise alignment for a speaker change inside one ASR segment. A useful follow-up experiment would compare word error and diarization error on consented, labelled fixtures before changing the default; Whisper word alignment would need implementation to match the present Parakeet path.

The installed Codex CLI `exec --help` and the [official non-interactive command reference](https://learn.chatgpt.com/docs/cli/reference) expose prompt text and image attachments, but do not document a recorded-audio file input suitable for this pipeline. Interactive voice dictation is not a supported batch meeting-transcription contract. No Codex-audio option is added. OpenAI's separate [file-transcription API](https://developers.openai.com/api/docs/guides/speech-to-text) is a cloud integration with different authentication/billing and capability constraints; Jottie does not silently route recordings through it. Codex continues to receive text only through the existing opt-in analysis workflow.

### Verification of this pass

All 60 Jottie tests pass, including alias collisions, source-name compatibility, passage-scoped attribution, low-confidence/contradictory suggestions, manual unknown overrides, default names without summaries, stale-edit protection, directory alias durability, transcript/search projection and MCP pagination. The inherited/capture suite passed 773 tests; a final focused rerun of the ten naming tests also passed after preserving the account-name fallback for a blank configured default. Blank legacy role fields now fall back to the uniquely matched BambooHR title rather than hiding it.

Native testing used an isolated invented library: verified reconciled rows, directory roles, undetected invitees, alias editing and SQLite persistence. A correction to exactly one of two passages saved the directory employee ID and job title, left the other passage unchanged, and merged the corrected passage into the proper speaker row. The first interactive check exposed a collapsed passage selector in the sheet; it now has an explicit bounded height and wrapping instructions.

Opening the real long meeting exposed repeated alias generation and speaker-label sorting on the UI thread. A 1,200-passage synthetic regression reproduced the slowdown at about five seconds. Per-calculation lookup tables and a normalized text projection reduce the combined speaker/undetected-invitee/display-name check to approximately 0.1–0.25 seconds on this machine. The real library subsequently opened responsively, and native typing verified default-name autocomplete against the existing directory without changing the user's preference. Only invented meeting corrections and aliases were written during UI testing; no real meeting was sent to Codex for these checks.

The bundle passed signature, embedded-framework startup and macOS 14.2 compatibility checks and replaced the same `.build/Jottie.app` path. Real voice-separation and identity accuracy still require daily meeting evaluation; automated tests establish deterministic validation and correction behaviour, not the correctness of an AI's inference about a real voice.
